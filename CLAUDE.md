# CLAUDE.md — StyleCut

> Working name: **StyleCut**. Rename freely; search-replace `stylecut`.

## What we're building

StyleCut copies the *style* of any viral short-form video and applies it to the creator's own footage.

**Core loop:**
`Reference URL/upload → Style Profile → Shoot Plan (Plan Mode) → Raw footage → Auto-assembled Timeline → Render → Tweak → Export`

1. **Analyze**: the user drops a YouTube Shorts / Instagram Reels / TikTok link (or uploads the file). We extract a structured **Style Profile**: pacing, cut rhythm, hook structure, caption look, zooms, b-roll ratio, music energy, SFX, color, narrative beats.
2. **Plan Mode**: given the Style Profile and the user's topic, we generate a **Shoot Plan**: script, shot list, framing, takes, and a filming checklist in shoot order. After upload, a **Coverage Check** flags missing shots.
3. **Auto-edit**: we build a **Timeline** (JSON edit decision list) from the user's footage that matches the profile, then render it with FFmpeg.
4. **Tweak & export**: the user edits captions, trims, and zooms in a light editor, then re-renders and exports 1080×1920 MP4.

## Stack (decided; don't swap without logging a decision)

- **Web**: Next.js 15 (App Router), TypeScript, Tailwind, shadcn/ui, TanStack Query. Mobile-first: Plan Mode is used on set from a phone.
- **API**: Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2 + Alembic.
- **Workers**: Celery + Redis. One queue per weight class: `io` (downloads, uploads), `cpu` (ffmpeg, scene detect), `gpu` (whisper, optional demucs), `llm`.
- **DB**: Postgres 16 (JSONB for profiles, plans, timelines).
- **Storage**: S3-compatible (MinIO locally). Presigned uploads straight from the browser.
- **Media/ML**: ffmpeg 7, yt-dlp, PySceneDetect, faster-whisper (word timestamps), librosa, pyloudnorm, OpenCV, MediaPipe (face tracking for 9:16 reframe). Demucs is optional (voice/music split).
- **LLM**: Anthropic API via the `anthropic` Python SDK. `LLM_MODEL_SMART` (default `claude-sonnet-5-5`) for synthesis/planning and `LLM_MODEL_FAST` (default `claude-haiku-5-5`) for classification. Vision input uses frame **contact sheets**, never raw video.
- **Render**: FFmpeg driven by Timeline JSON. Captions are ASS subtitles via libass.
- **Local dev**: docker compose (postgres, redis, minio, api, worker, web).

## Engineering rules

1. **Schemas are the contract.** `StyleProfile`, `ShootPlan`, and `Timeline` live in `stylecut/schemas/` as Pydantic models with a `schema_version` field. Change a schema → bump the version → write a migration function → run `make types`.
2. **Deterministic first, LLM second.** Anything measurable (cut times, shot lengths, BPM, loudness, word timings, WPM, color stats) is computed by code. The LLM only makes judgment calls: shot classification, narrative beats, hook type, take quality, emphasis words, script writing.
3. **The renderer is pure.** `render(timeline, assets) -> mp4`. No LLM calls, no network, no randomness. This makes it testable with golden files.
4. **LLM calls go through `stylecut/llm/client.py` only.** Use tool-use structured output validated by Pydantic. On validation failure, retry once with the error message appended. Log prompt id+version, model, tokens, latency, and cost on every call.
5. **Jobs are idempotent.** Key each job on `(subject_id, step, step_version)`, where the subject is the asset, project, or timeline the job works on. Artifacts go to deterministic S3 keys (see ARCHITECTURE.md), so a re-run overwrites cleanly and a cache hit skips the work.
6. **All ffmpeg goes through `stylecut/media/`.** Build commands as argument lists (never shell strings). Snapshot-test the generated commands.
7. **Work on proxies.** Analysis and preview renders use 540p proxies. Only final renders touch originals.
8. **Progress is visible.** Every job emits progress events (Redis pub/sub → SSE) with a human-readable step name.
9. **Style:** type hints everywhere, ruff format, mypy strict on `schemas/`, `edit/`, `render/`. TS strict mode. No `any`.
10. **Tests:** pytest for domain logic. Golden render tests on synthetic fixtures: assert duration, resolution, and frame hashes at checkpoints. Mock LLM calls with recorded fixtures (`tests/llm_cassettes/`).

## Guardrails (non-negotiable)

- **Reference media is analyzed only, never reused.** Never place reference video frames or reference audio into a user's output. Outputs are built only from the user's own footage, the user's uploads, and licensed library assets.
- **Reference media is temporary.** Delete downloaded reference files after analysis (S3 lifecycle: 24h). Keep only derived data: the StyleProfile, stats, and low-res contact sheets for the profile UI.
- **URL ingest sits behind `ENABLE_URL_INGEST`** and the `IngestProvider` interface. Direct file upload must always work as the fallback. Platform downloaders break often and are subject to each platform's terms, so the product must never depend on them.
- **Music and SFX** come only from user uploads or a licensed/royalty-free library. Never extract music from a reference.
- **No secrets in code.** Read everything from env (see below). Never log API keys or presigned URLs.

## How to work in this repo (instructions for Claude)

- **Start of a session:** read `PLAN.md`, find the first unchecked task in the current phase, restate it with its acceptance criteria, and propose an implementation plan. Wait for approval before writing code.
- **One task = one commit.** Keep diffs reviewable. Message format: `phase-N: <task>`.
- **When done:** run `make lint test`, check the box in `PLAN.md`, and add a line to the **Decisions log** at the bottom of `PLAN.md` if you made a non-obvious choice.
- **Ambiguity:** if a spec is unclear, add the question to `docs/OPEN_QUESTIONS.md`, choose the simplest option that keeps the schema contracts intact, and say which you chose.
- **Dependencies:** don't add a new library without noting it and the reason in the Decisions log.
- **Don't** jump ahead to later phases, rewrite specs silently, or replace deterministic code with LLM calls.
